# 代码规范与实验实现

Java 源码采用 Google Java Style，使用 `google-java-format 1.24.0` 的 GOOGLE 模式。Maven 的 Spotless 2.43.0 在 validate 阶段检查格式，`mvn verify` 会同时检查并编译。项目输出目标为 Java 17。

```bash
# 检查格式和构建
mvn -s scripts/maven-settings.xml -B verify
# 自动整理格式
mvn -s scripts/maven-settings.xml -B spotless:apply
```

格式规则包括两空格缩进、显式导入、一行一条语句、统一换行和大括号；类名采用 UpperCamelCase，方法和变量采用 lowerCamelCase，常量采用 UPPER_SNAKE_CASE。Spotless负责自动排版，命名和注释内容在代码审查时检查。

## 阅读顺序

1. `Application` 启动 Spring Boot，运行 profile 决定装配哪一套数据库实现。
2. `LogRequest` 声明共用写入约束，`LogController` 统一处理 ULID、UTC 毫秒精度及查询参数。
3. `LogStore` 定义单条写入和条件分页接口，`LogPage` 统一响应结构。
4. `MySqlLogStore` 通过 JPA 写入与分页，`LogJpaRepository` 提供动态条件查询。
5. `MongoLogStore` 通过 `LogMongoRepository` 执行 insert 和条件分页，保留与 JPA 相同的时间区间与排序。`MongoRepositoryConfiguration` 将仓储扫描限定在 mongo 包。
6. `LogEntry` 将公共业务字段映射到关系表和文档集合。

中文注释解释字段含义、分页口径、时间边界、ULID编码、事务提交和写入确认。连接池、数据库持久化与资源配置见 `application-*.yml`、`scripts/deploy.sh` 和报告方法章节。

## 实验控制和统计

`scripts/experiment.py` 按实现、读写操作、并发和重复编号组织运行；每次恢复10万条基准数据。`run-one.sh` 调用共用JMX，记录升压、预热和正式窗口。`audit.py` 使用请求开始时间，按 `[起点+40秒, 起点+160秒)` 复核正式样本。`analyze.py` 汇总每次结果和三次中位数，`build-report.py` 将已审计数据写入报告。

报告先讨论1、10线程的负载表现，再讨论1至200线程的逐级压力表现。两章使用同一组真实测量，原始时间顺序保存在每次运行的 `summary.json` 中。
