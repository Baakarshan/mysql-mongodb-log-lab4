# 课堂讲解与实验实现

本实验依据《实验四：MySQL与MongoDB日志读写性能对比实验》实现统一日志模型、单条写入和条件分页查询。课堂音频与老师仓库 `https://gitee.com/mingqcn/spring-fundamentals` 的 `6.SpringData_Mongo/order` 示例用于核对Spring Data访问方式。核对版本为 `854d0e09e250bc5462267f63ecacdcff32161104`。

MongoDB持久化采用MongoRepository：继承insert完成新增，通过查询注解定义日志级别及左闭右开时间范围查询，Pageable统一分页和排序。仓储扫描限定在mongo包，mysql profile继续使用原有JpaRepository。两套实现共用HTTP接口，持久化技术在LogStore之下替换。

实验使用单机MongoDB 7.0，四台主机分两轮复用。课堂后半段演示三节点副本集并只测试Primary；本实验PDF要求部署MongoDB 7.0，没有指定副本集。当前业务为单文档插入，未使用多文档事务。

读取负载固定查询INFO级别、UTC 06:00至07:00的第一页20条，并返回2497条匹配记录的总数。预热后持续访问相同查询，因此结果对应热点条件分页接口。按CSV中变化的主键读取单个订单属于另一种负载，应单独测量。

2026年11月12日将MongoTemplate实现替换为Repository后，重跑MongoDB全部36组正式测量，并重新进行接口验收、预试验、记录数核对和JTL审计。MySQL和公共代码以Java 17编译后比较方法指令与签名，并核对依赖和MySQL配置，确认一致后保留原36组测量。旧版代码、数据和报告可通过Git提交12616e4检索。

## 老师代码的实际调用

- `OrderMapper` 继承 `MongoRepository<Order, String>`。
- `OrderDao.insert` 调用 `orderMapper.insert`，`findById` 调用继承的主键查询方法。
- `CustomerController` 暴露 `/orders` 写入和 `/orders/{id}` 单对象读取。
- `ReadOrder.jmx` 使用 `Id.csv` 逐条提供读取ID；当前实验要求条件分页，因此保留固定级别和时间窗口请求。
- `MongoConfig` 注册 `MongoTransactionManager`，上述服务和DAO方法未标注 `@Transactional`。本实验单文档写入使用明确的确认与持久化配置。

本实验按日志实验要求统一ULID、UTC毫秒精度、业务字段和分页接口。
